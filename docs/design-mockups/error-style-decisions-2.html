Combo worth considering: O2 → O3. The toast appears the moment you go offline (impossible to miss), then after ~8s collapses into the header chip so it stops covering the board. Reconnect: chip disappears, lime success toast fires. State is always visible, urgency only when it's news.

Notes on the two calls

  • Red for destructive is a semantic upgrade, not just a preference. Today copper means both "something failed" and "you're about to do something irreversible" — two very different moments sharing one hue. Splitting them (copper = failure, red = destructive intent) makes both clearer. The label palette already ships the red, light and dark.
  • But commit to the ripple. If the confirm goes red while the Button destructive variant stays copper (R1), the app has two danger reds within one dialog. R2 means migrating Button variant="destructive" and the coherency rule ("copper for destructive") to red — a small sweep, worth doing in the same change.
  • Offline as a stuck toast (O2) is the most Kolumn answer. It reuses the exact grammar, position, and lifecycle users already know: warn toast arrives → state persists → lime toast resolves it. The pulsing dot is the only new element, and it earns its place by encoding "ongoing," which no static banner does.
