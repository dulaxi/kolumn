1 · The three primitives

Kolumn's loading vocabulary has exactly three primitives: Spinner (whole-view waits), Skeleton (content-shaped placeholders), and Button loading (in-flight actions). Everything else in this audit is either a composition of these or a hand-rolled deviation.

1.1

Spinner

src/components/ui/Spinner.jsx

Phosphor CircleNotch, weight bold, spun with Tailwind's animate-spin (1s linear infinite), colored --text-muted. Its own docstring restricts it to route/page-level fallbacks — "waiting for the whole view".

default (20px)
size={24} — the size every real usage passes
size={32}

CircleNotch bold · animate-spin 1s linear · color: var(--text-muted) · aria-label="Loading"

1.2

Skeleton unused in production

src/components/ui/Skeleton.jsx

4 variants × 2 tones. Default tone: --surface-raised + animate-pulse (opacity 1 → 0.5 → 1, 2s). AI tone: the ai-skeleton-block shimmer. Fully built and tested — but no production component imports it. Both real skeletons in the app (2.2, 4.1) are hand-rolled.

tone="default" — block · line · circle · pill
tone="ai" — same variants, shimmer fill

default: bg var(--surface-raised) + animate-pulse 2s · ai: linear-gradient(raised → mauve-wash → lime-wash → raised) 200% width, 2s ease-in-out

1.3

Button loading — the dots cycle

src/components/ui/Button.jsx:70-77 · src/index.css:372-387

No spinner icon. The button keeps its label (or swaps to loadingText) and a CSS-only .btn-dots::after cycles . → .. → ... at 1.4s steps(4). The button also gets disabled + aria-busy + the 50% disabled opacity. min-width: 1ch reserves space so the label doesn't jitter.

button-dots-cycle 1.4s steps(4, end) · disabled:opacity-50 · pointer-events-none · aria-busy="true"

3 · AI working states

The AI has its own loading language: the mauve→lime shimmer means "the AI is building this", and the glitching logo mark means "the AI is thinking". These are the brand's signature loading states.

3.1

AICardSkeleton — AI is creating this card

src/components/board/AICardSkeleton.jsx · src/components/board/SortableCard.jsx:36-42

Rendered in place of a kanban card while an AI tool call builds it (isAIBuilding(card.id)), held for a minimum 1.5s. Card-shaped: 16px radius (the deliberate kanban-card exception), --color-mist border, icon square + title/subtitle lines + description lines + two label pills — all ai-skeleton-block shimmer.

rounded-2xl (16px) · border var(--color-mist) · bg var(--surface-card) · shimmer 2s · min hold 1500ms in SortableCard

3.2

TypingIndicator — AI is thinking (chat)

src/components/chat/TypingIndicator.jsx · src/pages/ChatPage.jsx:54

The Kolumn kanban mark (Phosphor Kanban, fill, --color-logo) with a stepped "glitch-pulse" — opacity and scale stutter at 1.2s steps(5), reading as a heartbeat rather than a smooth pulse. Shown below the message list while the response streams.

glitch-pulse 1.2s steps(5, end) infinite · color var(--color-logo) · 16px · keyframes inlined in the component via <style>

4 · Hand-rolled skeletons & text-only waits

Two member-list surfaces load the same kind of data and present it completely differently — one with ghost rows, one with plain text. Neither uses the Skeleton primitive.

4.1

BoardShareModal — member ghost rows hand-rolled

src/components/board/BoardShareModal.jsx:233-245

Two ghost rows shown only on first open with no cached members, sized to keep the modal height stable. Built from raw divs with animate-pulse on --surface-hover — a different fill than the Skeleton primitive's --surface-raised, and rounded 4px vs the primitive's 6px.

avatar 28px circle · lines h-3 w-24 / h-2.5 w-32 opacity-60 · bg var(--surface-hover) + animate-pulse — primitive would use var(--surface-raised)

4.2

WorkspaceMembers — "Loading members…" text-only

src/components/workspace/WorkspaceMembers.jsx:13

The workspace-scoped member list — the same data shape as 4.1 — shows a static muted sentence inside the bordered card instead of ghost rows. No animation, no shape preservation; the card grows when members land.

Loading members…
