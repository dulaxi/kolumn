STILL YOUR CALL

The Description field is lying

The modal collects a description and then throws it away — createWorkspace(name, icon) has no description parameter. A user types one, hits Create, and it silently vanishes. Mockup B shows it kept, but that's a real decision:

  • Persist it — add a description column to workspaces (a migration) and thread it through the store. The field becomes true, and workspaces get a subtitle you could show on the landing tiles.
  • Remove it — drop the field entirely. Zero migration, and the modal stops lying today. Boards don't have descriptions either, so this is the consistent option.

My take

B, plus remove the description — at least for now. The visual rework is pure alignment with a pattern you already shipped, so it's low risk. The description is the only real product decision here, and "remove" is the honest cheap one: boards don't have descriptions, nothing renders a workspace description anywhere, and a field that silently discards input is worse than no field. If you want workspace subtitles later, that's a feature with a migration — not a leftover.

Bonus, and separate: border-0.5 renders nothing in 19 places app-wide. Worth its own sweep to border-[0.5px] — but it needs an eye, since some of those elements might look better with no border at all now that we know they've never had one.
